## Config provider

Three layers, later overrides earlier: defaults → injected config (a file exported earlier) → browser draft.

```jsx
export function deepMerge(base, override) {
  if (override === undefined) return base
  if (!isPlainObject(override)) return override

  const output = Array.isArray(base) ? [...base] : { ...base }
  Object.entries(override).forEach(([key, value]) => {
    const current = base?.[key]
    output[key] =
      isPlainObject(value) && (isPlainObject(current) || Array.isArray(current))
        ? deepMerge(current, value)
        : value
  })
  return output
}

/** "projects.0.title" → { projects: { 0: { title } } } */
export function patchForPath(path, value) {
  return path
    .split('.')
    .reduceRight((acc, key) => ({ [key]: acc }), value)
}
```

`Array.isArray(current)` in that condition is the whole point: `patchForPath('projects.0.title', v)`
is a plain object, so without it the projects array is replaced by `{ 0: … }`.

Sanitize once on load so older drafts cannot brick the page:

```js
const ARRAY_PATHS = ['nav', 'projects', 'skills', 'courses', 'stack', 'contacts',
  'experience', 'education', 'widgets.items']

export function sanitizeConfig(config) {
  let next = config
  for (const path of ARRAY_PATHS) {
    const value = readPath(next, path)
    if (Array.isArray(value)) continue
    const fixed = coerceArray(value, readPath(defaultConfig, path) ?? [])
    next = deepMerge(next, patchForPath(path, fixed))
  }
  return next
}

// objects keyed by digits came from the old bug — turn them back into arrays
const coerceArray = (value, fallback) => {
  if (Array.isArray(value)) return value
  if (isPlainObject(value)) {
    const indexes = Object.keys(value).filter((k) => /^\d+$/.test(k))
      .sort((a, b) => Number(a) - Number(b))
    if (indexes.length) return indexes.map((k) => value[k])
  }
  return fallback ?? []
}
```

## Editor gating

```jsx
const injected = window.__SITE_CONFIG__ ?? null
const isLocalFile = location.protocol === 'file:'
const wantsEditor = new URLSearchParams(location.search).has('edit')

// Exported files carry a config, so they never expose the editor.
const editorEnabled = injected ? false
  : Boolean(BUILD_HAS_EDITOR && (isLocalFile || wantsEditor))
```

Scope the draft per document — every `file://` page shares one storage area:

const key = `site-config:${location.pathname || '/'}`

## Editor shell

- Panel is a fixed right-hand drawer; body scrolls; footer holds the actions (export, export/import config JSON, reset).
- Tabs map to content areas the user thinks in (hero / projects / about / skills / contact / widgets).
- Field components stay tiny and uniform: `label` + value + `onChange`. A line-list field should keep local text while focused so pressing Enter does not eat the current line.
- Image upload: read the file, downscale on a canvas (1600 px longest edge), store the data URL in the config so exports stay self-contained.
- Advanced parameters live behind a collapsed "高级选项" toggle; show the effect selector alone by default.

## Double-click to edit

```jsx
export function Editable({ focusId, tab = 'basic', as: Tag = 'div', className = '', children, ...rest }) {
  const { editorEnabled } = useConfig()
  const { focusBlock, setOpen } = useEditorUi()
  if (!editorEnabled) return <Tag className={className} {...rest}>{children}</Tag>
  return (
    <Tag
      className={`${className} is-editable`.trim()}
      title="双击编辑这一块"
      onDoubleClick={(event) => {
        event.preventDefault(); event.stopPropagation()
        setOpen(true); focusBlock(focusId, tab)
      }}
      {...rest}
    >
      {children}
    </Tag>
  )
}
```

On the panel side, mark each control with `data-focus-id` and run one effect that scrolls and
highlights the match after the tab switch renders. Delay the scroll (~160 ms) so it accounts for
any collapsible section expanding.

## Export

```js
export function buildStandaloneHtml(config) {
  const payload = JSON.stringify({ ...config, editorEnabled: false }).replace(/</g, '\\u003c')
  const injection = `<script>window.__SITE_CONFIG__=${payload};</script>`

  // SLIM_TEMPLATE is generated by scripts/embed-template.mjs before the editor build
  if (SLIM_TEMPLATE && !needsHeavyBundle(config)) {
    return SLIM_TEMPLATE.replace('</head>', `${injection}</head>`)
  }

  // fallback: clone the live document, empty the mount node, inject into <head>
  const clone = document.documentElement.cloneNode(true)
  clone.querySelector('#root')?.replaceChildren()
  const script = document.createElement('script')
  script.textContent = `window.__SITE_CONFIG__=${payload};`
  clone.querySelector('head').insertBefore(script, clone.querySelector('head').firstChild)
  return `<!doctype html>\n${clone.outerHTML}`
}

export function downloadFile(filename, content, type = 'text/html;charset=utf-8') {
  const url = URL.createObjectURL(new Blob([content], { type }))
  const link = document.createElement('a')
  link.href = url
  link.download = filename
  document.body.appendChild(link)
  link.click()
  link.remove()
  setTimeout(() => URL.revokeObjectURL(url), 4000)
}
```

Export order matters: build the site → embed that build as the template → build the editor.

## Build modes

One project, several variants via Vite modes (see `assets/vite-single-file/vite.config.js`):

| Mode | Output | Contains |
| --- | --- | --- |
| `vite build` | `dist/` | published site, no editor |
| `--mode editor` | `dist-editor/` | editor on, owner-gated |
| `--mode editor-public` | `dist-editor-public/` | editor for every visitor |
| feature modes (`--mode lanyard`, …) | own folders | optional heavy features |

Gate optional heavy code at build time so the light variant stays light, and verify with a grep for
a marker string (for example `WebGLRenderer`) in each output.

## Placed widgets

Free-positioned components over the page (position stored as `x` percent of the layer width, `y` px
from the document top) are a common ask once the editor exists:

- Layer is `position: absolute; inset: 0; pointer-events: none`; each widget re-enables pointer events.
- Drag from the palette: attach `pointermove`/`pointerup` listeners **synchronously in the
  `pointerdown` handler**, not from a React effect — a fast drag delivers every move before React
  commits the state update, and the listeners would miss them.
- Resize: show handles on the selected widget (right edge, bottom edge, corner). Dragging writes
  `w`/`h` on the item and maps them onto the component's own size props where one exists
  (card `width`, avatar/QRCode `size`) so the content scales instead of just the box.
- Entrance effect per widget: a small map of `{ initial, animate }` pairs (fade, scale, blur, slide)
  applied with `motion.div` + `whileInView`; keying the element on the effect name replays it on change.
